# Reflow Hotplate — Hardware (Schematic + Board) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a KiCad 10 schematic and a single-sided, through-hole, CNC-millable control board for the ESP32 reflow hotplate, with production files ready for the Roland SRM-20.

**Architecture:** One control board (spec Approach A). A 24 V input feeds an LM2576 switcher (5 V logic) and an LM7812 (12 V gate-drive rail). An IRFS4710 low-side MOSFET switches the 13 A heater through wide copper pours in an isolated "power corner"; a two-stage non-inverting BS170 level shifter drives its gate boot-safe. An ESP32 DevKit reads a MAX31855 thermocouple over SPI and drives an SSD1306 OLED + rotary encoder + start button. Built with a Python schematic-generator script (the project's established `build_v1_schematic.py` pattern), then routed/exported via the `kicad-laser-pcb` skill and milled per `SRM20_MILL.md`.

**Tech Stack:** KiCad 10.0 (CLI + s-expression `.kicad_sch`/`.kicad_pcb`), Python 3.13 + `sexpdata`, the `kicad-laser-pcb` skill scripts (`pcb_build.py`, `route_board.ps1`, `export_production.ps1`, `bom_to_md.py`), Freerouting (Java 21).

## Global Constraints

- **KiCad version:** KiCad **10.0** only. CLI at `C:\Program Files\KiCad\10.0\bin\kicad-cli.exe`; pcbnew Python at `C:\Program Files\KiCad\10.0\bin\python.exe`. The 9.0 CLI cannot read these files. Pass `-KicadBin "C:\Program Files\KiCad\10.0\bin"` to `route_board.ps1` / `export_production.ps1`, and set `KICAD_LASER_EXTRA_LIBS` to this repo's `hardware/kicad/lib` when running `pcb_build.py`.
- **Design rules:** track **1.0 mm**, clearance **0.8 mm**, single-sided (B.Cu copper), **through-hole only**, top-layer nets realised as wire bridges (`*_top_cu.dxf`). Do not lower these — they come from the mill/laser process.
- **Footprint libs (vendored into repo, project-local `fp-lib-table` with `${KIPRJMOD}` relative paths):** `energy_system.pretty` (TO-220 `_LaserPads_GDS` variant for the MOSFET, plain `_LaserPads` for regulators) and `TerminalBlock.pretty` (bornier P5.08 mm). Source of truth: the DTU Electrical Energy Systems repo `hardware/kicad/lib/`.
- **Sourcing rule:** every part **soldered to the board** must resolve to a row in `components-inventory/dtu_component_shop(1).csv`. Modules (ESP32 DevKit, MAX31855, SSD1306) mount on female headers / Molex and are *not* board-soldered parts.
- **Pin map:** exactly as spec §8.1. `HEATER_PWM=GPIO25, TC_SCK=GPIO18, TC_SO=GPIO19, TC_CS=GPIO5, OLED_SDA=GPIO21, OLED_SCL=GPIO22, ENC_A=GPIO32, ENC_B=GPIO33, ENC_SW=GPIO27, BTN_START=GPIO26, LED_STATUS=GPIO4`.
- **Commits:** never mention Claude/AI in commit messages (user standing rule).

### Task 5: Wire the power stage (MOSFET + boot-safe gate drive)

**Files:**
- Modify: `build_schematic.py` (`NETS_POWERSTAGE` pass), `reflow.kicad_sch`, `docs/electrical-calcs.md`

**Interfaces:**
- Consumes: `+12V`, `GND`, `HEATER_PWM` label, `J2` heater terminal.
- Produces: nets `HEATER_RET` (Q1 drain), `GATE_MAIN` (Q1 gate), `GD_NODE1` (inter-stage).

Two-stage **non-inverting, boot-safe** level shifter (GPIO high → heater on; low/floating → off):
- Stage 1 inverter: `R1` (100 kΩ) gate pulldown on `Q2.G` to GND; `HEATER_PWM → R2 (1 kΩ) → Q2.G`; `Q2.S=GND`; `Q2.D = GD_NODE1`; `R3` (10 kΩ) pull-up `GD_NODE1 → +12V`.
- Stage 2 inverter: `GD_NODE1 → Q3.G`; `Q3.S=GND`; `Q3.D = GATE_MAIN`; `R4` (10 kΩ) pull-up `GATE_MAIN → +12V`; `R5` (100 Ω) is the series gate resistor from `GATE_MAIN` to `Q1.G`; `R6` (10 kΩ) gate-source pulldown `Q1.G → GND`.
- Power loop: `J2.1 = +24V` (heater +), `J2.2 = HEATER_RET`; `Q1.D = HEATER_RET`, `Q1.S = GND`. `D4` TVS (e.g. SMBJ33-equiv THT) across `HEATER_RET → GND` clamps drain transients.

Boot-state proof to record: GPIO floating → `Q2` off → `GD_NODE1` = +12 V → `Q3` on → `GATE_MAIN` = 0 V → `Q1` off. ✓

- [ ] **Step 1: Add the boot-safety assertion test** — `tools/check_gate_boot_safe.py`: parse the netlist; assert `GATE_MAIN` has a path to GND through `Q3` and a pull *down* dominates when `HEATER_PWM` is low (encode as: `R6` connects `Q1.G`→GND, and `GD_NODE1` pull-up to +12V exists). Exit nonzero if the inverting (single-stage) pattern is detected (`HEATER_PWM` pull-up directly to gate).

- [ ] **Step 2: Run it — expect failure** (stage not wired). Expected: nonzero exit.

- [ ] **Step 3: Implement `NETS_POWERSTAGE`** with the connections + resistor values above; add `Q3`, `D4`, `R1..R6` values.

- [ ] **Step 4: Add the power calcs** to `docs/electrical-calcs.md`: Q1 conduction loss = I²·Rds(on) = 13²×0.014 ≈ 2.4 W → TO-220 heatsink + pad; gate charge vs. 12 V/Rg switching time ≪ PWM period; confirm Vgs=12 V < Vgs(max) 20 V and ≫ Vgs(th).
